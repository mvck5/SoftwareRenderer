----General information----
coordinate system is right handed
matrices are in column-major order
winding is 
coordinates start in the bottom left
only object files supported are obj


----Rendering pipeline----
Load in vertex and index data
create model-view-projection matrix from object's model, cameras view and general projection matrices
create normal matrix (usually a transpose of the upper left 3x3, if non uniform scaling used then we have to use the normal inverse)
for each triangle:
-for each vertex in triangle: pass vertex to vertex shader, along with the model-view-projection matrix
--VERTEX SHADER--
transform vertex attributes
Position: by model-view-projection matrix
Normal: by normal matrix
Texture: no transformation
transform by projection matrix without perspective divide(don't divide by w) to get to clip space
perform clipping(for now do a basic check if x,y,z are within the absolute value of w and w is greater than 0)	
perform perspective divide(divide by w) to get to NDC(normalised device coordinates)
viewport transform(goes from -1,1 to 0,1)
-pass transformed triangle to rasteriser
--RASTERISER--
determine which pixels are covered by the triangle
compute barycentric coordinates
-for each "fragment"(pixel as we do no anti-aliasing) pass to fragment shader, along with any relevant texture and lighting data
--FRAGMENT SHADER--

--various culling techniques:
frustrum - discard objects outside the camera’s viewing volume
this would involve creating AABB(axis aligned bounding box) by which we can check if all 6 vertices are contained within the frustrum
if all 6 vertices of the bounding box are not within the frustrum we wouldn't draw the object
this would also be useful for collision

occlusion - discard objects completely hidden behind other geometry

bounding box(technically already done, but could be optimised) - test an object’s bounding box before processing its detailed geometry

near/far - remove geometry outside the camera’s depth range

screen space - clip primitives against the viewport to avoid unnecessary rasterisation

-Tiling
we can check the corner pixels of a "tile" and if all of those are true for the triangle then we can simply draw
without any further checks needed. if the corners aren't filled then we can subdivide the "tile" further
example: check an 8x8 tile's corners, if false check 4 4x4 tiles, if false check 16 2x2 tiles, if false check 64 pixels
